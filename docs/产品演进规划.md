# 人格测试树 · 产品演进规划（讨论稿 v0.1）

> 定位：这是一款**已经上线的纯静态工具型小程序**。它现在的问题不是"不好用"，而是**用完即走、走了不回来、带来的人接不住**。
> 这份文档从产品经理 + 用户两个视角，说清楚：先修什么、再做什么、可以选哪条路。

---

## 一、现状盘点（代码事实，不是印象）

| 项 | 现状 | 出处 |
|---|---|---|
| 测试内容 | 6 套：SBTI、MBTI、九型、大五、阴影人格、E/I | `data/tests/index.js` |
| 主包体积 | 约 1.4MB，其中 1.3MB 是 SBTI 的 27 张结果图 | `data/tests/images/` |
| 后端 | 无。无登录、无用户体系、无任何埋点 | 全局 |
| 报告保存 | 明确告知"不保存，请自行截屏" | `pages/test-result/index.wxml:29` |
| 分享 | 结果页有悬浮分享 + 朋友圈分享 | `pages/test-result/index.js:143` |
| 用户中心 | 只有产品介绍、免责声明、版本号；反馈按钮点了弹"开发中" | `pages/user-center/` |
| 订阅消息 / 回访 / 多测联动 | 都没有 | — |

**一句话诊断**：产品有"内容"，但没有"用户资产"和"增长闭环"。用户增长慢是必然结果，不是运营不到位。

## 二、三个必须先说的判断（P0）

### P0-1　分享链路是断的，朋友圈那条路是死锁
结果页分享路径写死 `/pages/test-result/index?id=xxx`。被分享的人没做过测试，本地没有 `testResult`，代码会把他**强行送去答题页**（`test-result/index.js:122` 的 `loadResult` 分支）。

用户视角的真实后果：A 兴冲冲晒了"我是 BOSS 型"，B 点进来一脸懵地被丢进题库开始答题 —— **这就是转化率最低的那一步，也是你增长慢最直接的原因**。晒的人多了，进的人应该多；现在晒得越多，流失得越难看。

> 修好这一步（让被分享者看到"别人的报告 + 我也测一个"），是**成本最低、确定性最高**的增长动作。

**补充（已核实两处更严重的事实）**

1. **朋友圈那条路是死锁，不是低效。** 朋友圈打开小程序走"单页模式"（scene 1154）：本地存储隔离 + **禁用路由跳转**。此地被分享者本地同样没有 `testResult`，`loadResult` 会去执行 `wx.navigateTo` —— 单页模式下该调用被禁用，用户看到的是**空白结果页**。朋友圈是这个品类最强的曝光场，现在入口等于封死。
   （好消息：`onShareTimeline` 基础库 2.11.3 起 Android/iOS 均支持，iOS 需微信 8.0.24+；项目 `libVersion 2.30.0` 满足，纯粹是页面逻辑没兜住。单页模式还要求：不能靠登录态、不能引导"必须打开完整版才能看内容"，否则违反反诱导政策。）
2. **分享面只有结果页一个口子。** 5 个页面里只有 `test-result` 实现了 `onShareAppMessage`，测试大厅和详情页没写转发钩子。新用户进来没有任何"把小程序分享出去"的出口，只能自己右上角三个点硬转发（且卡片标题是默认的"人格测试树"，毫无钩子）。

**修复方向（阶段 0 内可全部完成，不动架构）**：结果页把"有没有本地结果"分成两种渲染 —— 有则渲染云端/本地参数化的**自己的**报告；没有则渲染一张**该测试的类型图鉴页**（列出 16/27 种类型 + 每种一句话钩子 + "我也要测"按钮）。这样任何路径进来都不空白，且天然适配单页模式（纯展示、不跳转）。

### P0-2　没有任何数据，所有决策都是猜
没有埋点，你不知道：每天多少人、多少人做完测试、做完多少人分享、分享带来多少新用户、哪套测试最受欢迎。
**没有漏斗就没法优化**，"优化转化率"这句话现在无法验证。这是继分享链路之后第二件要做的事。

### P0-3　"不保存报告"把复访理由亲手扔了
工具型小程序的三条命：**分享钩子、留存资产、回访触发**。你现在三条全空。
"不保存"是纯静态架构带来的限制，不是产品理念。解法见第四章（需要引入后端）。

## 三、非功能性：性能 + 微信评分 + 搜索曝光

### 3.1 首屏性能
1. **SBTI 图片改懒加载 + 分包**。现在 27 张图（1.3MB）全部打进主包，但用户一次只看 1 张。
   - 短期：`<image lazy-load>` + 把 `data/tests/images` 挪进 SBTI 相关分包，主包降到 ~100KB 级。
   - 长期：图片上 CDN（云存储），包内一张不放。
2. **答题页每次切题都 setData 整个 answers 数组**（`test-answer/index.js:88`），30 题时是明显开销。改成只更新变化的那一位。
3. **测试数据三处页面各自 `require` 全量 6 套**（hall / detail / answer / result），每次冷启动重复解析。放 `app.js` 全局数据或按需只加载当前这套。

### 3.2 微信评分与口碑
微信没有"评分影响搜索排序"的公开算法，但**评价数、差评率会影响信任度与转化**，且低分会抑制分享意愿（用户不想给自己打 2 分的app背书）。可做的：
- **反馈入口真正接通**（现在弹"开发中"，这是最刺眼的半成品）。接云数据库一张表即可，成本极低。
- **引导评价**：用户完成测试且停留超过 N 秒后，用官方 `wx.requestSubscribeSystemMessage` / 小程序评价接口引导（合规，别做"好评才能看报告"这种违规诱导）。
- **差评止损**：反馈入口比应用商店评价更近，先把不满导到自己的通道。
- **合规风险自查（重要）**：SBTI 结果类型里含 `FUCK`、`SHIT`、`POOR` 等露骨词（`data/tests/sbti.js`）。**这类内容不能作为小程序名称、简介、分享封面图**，否则一旦被判低俗，处罚是搜降权甚至下架，比不增长严重得多。建议保留在结果页里，但分享出去那张图（`imageUrl: result.image`）要挑安全的类型。

### 3.3 微信搜索曝光（现在 0 投入、收益最快的一块）
微信小程序搜索的主要自然流量来源：**名称、简介关键词、页面路径（sitemap）、被分享次数**。
- `sitemap.json` 现在只 allow 全部页面，没有结构化参数。补 `sitemapLocation` 里的 params（如 `id`），让每个测试详情页可被索引。
- **每套测试一个可被检索的落地页**：详情页要有自然语言描述（"MBTI 16型人格测试 免费 中文"这类），页面标题动态设置 `wx.setNavigationBarTitle` + `Page.json` 的 `navigationBarTitleText`。
- **名称/简介关键词**：主页文案现在只有"基于心理学理论的人格测试小程序"，没有覆盖搜索意图词（MBTI / 十六型 / 九型人格 / i人e人 / 人格测试）。
- **冷启动入口**：`app.js` 的 `onLaunch` 里读 `scene`，区分"来自分享 / 来自搜索 / 来自历史"，这是后面所有漏斗分析的分组依据。

## 四、功能性：粘性 + 增长获客（按用户视角）

### 用户为什么回来？三个理由，逐个补

| 理由 | 现在的状态 | 要做的事 |
|---|---|---|
| **我的报告在这里** | 无 | 报告存云端，个人中心变成"我的测评档案" |
| **我变了，想再看一次** | 无 | 复测 + 前后对比（"半年后你的 E 值涨了 20%"这种，天然可晒） |
| **有人在等我 / 有人要看** | 无 | 关系向测试（双人匹配）、结果排行榜（"公司里 INTJ 占比"） |

### 用户为什么会带人来？三个钩子
1. **分享卡片本身要好看**：现在分享出去是一张系统截图样式卡片。做成**生成海报图**（结果类型 + 图 + 一句金句 + 小程序码），用户存图发朋友圈/群 —— 这是这类产品最强的一条路，SBTI 那 27 张图本来就是为这个设计的。
2. **被分享者有专属承接页**（对应 P0-1）：看到"TA 是 BOSS 型" → 一句钩子"你是什么型？30 秒测完" → 直接进答题。**不要要求登录。**
3. **悬念型钩子**："你的阴影人格还没测"、"做完 MBTI 的人 82% 会再做这一套" —— 用推荐位把 6 套串起来，一个用户榨出 6 次使用。这是零成本内容改造。

### 关于"要不要收费"
只有三条现实路径：**流量主广告**（需要 DAU 门槛，现阶段量级远不够）、**付费深度报告**（需要长报告内容 + 支付 + 类目资质）、**导流到私域/其他产品**（需要你自己有下游）。
我的判断：**现在一条都别选**。当前唯一目标是留存和分享率，加钱会让转化率再掉一截，先把漏斗跑通再谈变现。

## 五、要不要后端？（这是最关键的架构选择）

上面几乎所有事都卡在同一个前置条件：**得有用户身份和存储**。

**推荐路线：微信云开发（TCB）**
- 不要自建服务器。已有 appid，云开发开通即用，按量计费，个人项目免费额度基本够用。
- 一次性解锁：静默登录（`wx.login` 拿 openid，用户无感）、报告存储、反馈提交、订阅消息、埋点落库、CDN 图片。
- 代价：小程序从"纯静态"变成"有后端"，需要**更新隐私政策并声明收集信息**（人格测试结果属于用户敏感信息，必须在 `app.json` 配 `__usePrivacyCheck__` 与隐私协议，否则不能弹窗收集）。合规这一步别省。

**不推荐路线（先放着）**：H5 版本、跨端 App、AI 解读报告。前两者工程量断层；AI 解读需要模型成本，且当前没有能让用户觉得"值"的场景，等报告体系建好再说。

## 六、路线建议（默认主推）

**阶段 0 · 修漏斗（1 周内，纯前端，不动架构）**
- 修分享落地页，被分享者能正常看报告 + 一键"我也要测"
- 加埋点：页面访问、开始答题、完成答题、提交、分享点击、来源 scene
- 反馈入口接通（先落本地缓存/邮箱，别卡在"开发中"）
- SBTI 图片懒加载，检查并替换不安全的分享封面图
- 详情页文案 + 导航标题做关键词

**阶段 1 · 建用户资产（2~3 周，引入云开发）**
- 静默登录 + 报告上云 + "我的测评档案"个人中心
- 结果海报生成（含小程序码）
- 推荐位串 6 套测试

**阶段 2 · 拉复访（2~3 周）**
- 复测 + 历史对比图
- 订阅消息（报告生成通知、每周人格洞察，注意微信订阅消息必须用户主动点，不能随便推）
- 个人中心真实化

**阶段 3 · 增长实验（按数据挑一个）**
- 双人/关系匹配测试（TA 眼里的你 / 情侣契合度）
- 圈子榜（群内人格分布）、企业/校园专场
- 变现（此时才评估）

**每阶段的验收指标**（先定后做）：
- 阶段0：分享落地页完成率 > 20%；拿到完整漏斗数据
- 阶段1：人均完成测试数 > 1.5；分享率 > 10%；K 因子 = 新增来自分享占比
- 阶段2：7 日回访 > 8%；报告保存率 > 40%

## 七、分支选项（等你拍板，我再展开对应方案）

- **A 主推路线**：阶段 0 → 1 → 2，以"报告资产化 + 分享闭环"为核心（我认为唯一能解开当前死结的组合）
- **B 不引入后端**：只做阶段 0 + 图片海报 + 内容扩充。工程量小，但复访和留存天花板很低（本地缓存清一次就没了）
- **C 内容优先**：加更多测试（依恋类型、职业倾向、情绪、ADHD 倾向等）+ 每套做精品长报告，靠内容差异化和搜索词吃流量。慢，但护城河真实
- **D 先做增长实验**：直接上双人匹配/圈子榜这类强社交玩法，赌单点爆款。风险最高，可能白干

## 八、评审必答清单

1. 你愿意为它持续投入多久、每周多少时间？（决定 B 还是 A/C）
2. 能接受引入云开发和用户数据吗（涉及隐私合规、月费）？
3. 有没有微信之外的分发阵地（公众号、群、私域）？有的话阶段 0 的价值会放大很多。
4. 这套东西对你而言是作品、练手，还是要增长的生意？三者做法完全不同。
5. SBTI 这类网络梗内容是你的主打还是顺带？它决定要不要往合规更稳的方向偏。

## 九、增长飞轮到底在哪（回答"是不是靠公众号引流"）

### 9.1 先定义飞轮
飞轮 = **每一圈的结果会喂下一圈**，不靠外部持续投喂。判断标准很简单：停止投入资源后，它自己还转不转？

公众号不满足这个定义。它是**单向漏斗**：文章 → 点进小程序 → 结束。文章不会因为你小程序里发生了什么事而变得更好，读者也不会自动变成传播者。它是"渠道"，不是"轮"。而且它要求你**持续产出内容**——独立开发者做内容，普遍活不过第 5 篇。

### 9.2 你这个品类唯一的天然飞轮：身份标签的自我复制
人格测试的产物不是一个分数，是**一个身份**（"我是 BOSS 型"）。身份是用来公开的，公开就会勾起动因——因为人想知道自己是什么。

```
有人测 → 拿到一个可以公开的标签 → 为了"让别人看到我是这个类型"而晒
      → 看到的人产生同一个动因 → 他也测 → 他也晒 →
```

这个环在你已有的产品里就成立，**不需要新内容、不需要广告费、不需要写文章**。SBTI 那 27 张图的存在证明你当初就是按这个逻辑设计的，只是环上有三处断口（见 P0-1、P0-2、P0-3）。

**飞轮的度量口径（定了才能判断有没有转起来）：**
- 分享率 = 分享次数 / 完成测试人数
- **K 因子 = 每个老用户带来的新用户数**（分享次数 × 分享落地转化率）
- 新增中"来自分享"场景（scene 1007/1008）的占比 —— 这个数字现在你完全不知道

**K 因子 > 0.15 且分享来源占比在涨 → 飞轮在转，加大投入；否则不是运营问题，是环本身没接通。**

### 9.3 第二个轮（更慢，但会自增强）：使用数据 → 搜一搜排名 → 更多使用
搜一搜是微信小程序最大的自然新增来源，业内公认的权重因子包括：**名称/简介与搜索词的匹配度、小程序质量与体验、活跃度与使用时长、页面被访问深度、分享次数、评价**（详见文末来源，微信不公开算法，此为业内共识而非官方承诺）。

注意这条对你原本的想法是个重要修正：

> **"优化性能提分"不是为了好看，它是排名权重因子。** 而比性能更硬的是**使用时长和完成率**——这两个指标直接由"内容够不够多、单次体验够不够厚"决定。所以性能是第 3 优先，**内容量和完成深度是第 1 优先**。
>
> 同时这两个轮**互为燃料**：分享带来的使用会抬高排名，排名带来的新用户会产生更多分享。这才是你真正要的"双轮"。

### 9.4 那公众号的正确定位是什么
不是引流主渠道，是三件事：
1. **搜一搜的信任背书**：搜"人格测试"时，有同名公众号 + 内容的小程序，转化更高。
2. **沉淀长内容**：16 型/27 型的深度解读放公众号，小程序只做 30 秒轻测试 + 结果，长报告导流过去。**顺便解决"小程序内不能诱导打开外部页面"的合规姿势问题。**
3. **私域收容**：把想复测、想要提醒的人收进可反复触达的地方，弥补微信订阅消息必须用户逐次点击的限制。

但**优先级低于修飞轮本身**。环没接通时，公众号引流来的人一样流失，只是让你更清楚地看到漏斗在漏。

### 9.5 冷启动的"第一把电"从哪来（飞轮需要种子）
环成立不等于自动启动，需要一批初始用户进去转第一圈。三个候选，成本递增：
- **种子社群**：找 10~30 个真人（同学群、兴趣群、同事群）先测先晒，同时充当第一批反馈。零成本，且立刻能验证"晒出去到底有没有人点"。
- **站外内容切片**：把 27 种 SBTI 结果图本身当素材发（小红书/豆瓣人格测试话题）。注意站外到小程序有跳转摩擦，转化率远低于微信生态内，只适合做声量不适合做增长主线。
- **公众号 + 搜一搜关键词卡位**：慢，但是唯一会随时间自动变强的那条。

### 9.6 这一节改变了路线的哪个假设
原第六章的阶段 0~2 不变，但**重心排序要调**：

| 原来的说法 | 修正后 |
|---|---|
| 性能优化提分 | 排到第 3。先做分享链路 + 埋点，再用真实数据决定优化哪一段 |
| 阶段 1 建报告资产 | **优先级下降一档**。飞轮的起点是"晒 + 接得住"，不是"存下来"。存报告解决的是回访，回访是第二阶段的问题 |
| 新增 | **阶段 0.5：把 5 个页面全部补齐分享钩子 + 结果页做"图鉴页兜底" + 埋点跑通 K 因子**。这三件事纯前端、一周内可完成，且是飞轮能否成立的最小验证 |

**判断标准**：如果做完这批，分享来源占比开始动，就继续往阶段 2 走；如果一点没动，说明问题在"内容本身没有社交货币属性"，那时该讨论的是换主打测试（MBTI 的传播性 > SBTI 的猎奇性？），而不是继续加功能。
