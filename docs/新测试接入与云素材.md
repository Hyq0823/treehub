# 轻测试接入约定

新增的古人人格投影、轨道／旷野生活偏好与隐藏天赋探索都使用同一套多维情境评分配置。结果仅描述本次自评偏好；古人是共鸣意象，不是对其生平的心理测量；天赋是值得尝试的兴趣方向，不是能力或职业鉴定。

## 注册清单

1. 在 `data/tests/` 新建题库，使用 `createProfileTest` 声明维度、题目、结果原型与专属解读。
2. 在 `data/tests/index.js` 注册完整题库，在 `data/test-catalog.js` 添加同序的轻量元数据与结果标题。轻量目录不得引入完整题库，保持大厅首屏开销可控。
3. 在 `data/exploration.js` 配置分类、入口文案、颜色与现有 CSS 图形；在大厅的展示顺序中加入测试 ID。
4. 需要结果影响树种时，在轻量目录的 `treeAssociations` 声明允许的维度范围与结果意象。关联不代表人格优劣；同一测试重复完成不增加探索等级，最新记录才贡献树形线索。
5. 在 `cloudfunctions/treehub-api/index.js` 的 `TEST_IDS` 中加入 ID 并部署云函数，使新测试参与云端探索条件校验。云备份继续仅保存摘要，不增加逐题答案或无关个人资料的收集。
6. 运行目录一致性、评分、档案、报告及云端校验测试，防止出现大厅能选但报告或云恢复无法识别的测试。

已发布的题目、计分和结果原型保持不可变。轻测试配置带 `testVersion`（首版为 `1`），记录保存相同版本；未知版本不能按当前规则重新解读。同一测试升级评分时，通过 `retainedVersions: { '1': previousTest }` 保留旧版完整解读配置，或使用新的测试 ID；不要原地覆盖已发布定义。`previousTest` 需由 `createProfileTest` 创建独立计分闭包。复测只对比同题库版本与同评分版本。

## 素材铁律

测试与主题业务图片全部走云端，本地代码包不放业务图片，也不提供本地图兜底。这三套测试先使用现有 CSS 图形和文字结果，不依赖新增图片，因此无需额外上传素材即可完成测试。

后续增加插画时，上传到云存储根目录下的 `public/v2/tests/<test-id>/`，代码仅配置去掉 `public/v2/` 前缀的 `assetPath`。实际上传完成后再配置，避免声明不存在的文件。云函数按安全相对路径解析，不需要逐张图片改代码；`public` 是目录名称，无需为它修改整个存储的访问权限。

保持新版本素材独立目录或文件名，不覆盖线上版本依赖的对象。素材加载失败时保留 CSS 占位与答题功能，不影响答题和报告保存。
