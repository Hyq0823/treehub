# 人格测试树：产品、分享与微信搜一搜设计

本轮面向喜欢自我探索、生活记录与精致数字收藏的小红书用户。视觉以浅蓝、奶油白和精致 3D 伙伴为主；产品不要求用户提供性别、年龄或社交账号，也不把审美偏好当作性格诊断。

## 用户能立刻得到什么

第一份测试完成后，用户应得到可阅读的基础报告、一棵本身就精美的树，以及可选择的基础伙伴主题。开始探索不需要先看广告，也不需要先上传答题记录。后续新测试带来成长叶片、主题推荐和新伙伴；复测保留过去的记录，让用户看到同一维度随时间的变化。

底部菜单固定为「探索｜我的树｜档案」。探索承担选测试和下一步引导；我的树集中展示主题、伙伴、成长与分享；档案负责历次报告、隐私和数据管理，避免资产内容与个人结果混在一个长页面里。

九套主题是不同的视觉意象，不分人格优劣。测试结果提供推荐，用户可以选择和切换已经获得的主题，不永久绑定某种标签。极光水镜采用隐藏剪影与探索线索，形成发现的乐趣。

## 广告与留存

- 基础报告、已有记录和首次主题持续可用。普通主题通过完整观看一次视频解锁该主题，深度报告通过完整观看一次视频解锁当前这条报告；两个权益分别提示、分别记录。
- 隐藏主题先满足探索条件再提供视频解锁入口，明确显示当前进度，不使用虚构稀有率或倒计时。
- 用户进入结果页后先看到自己的结果和价值，再自主选择深度解读或主题；不自动连续弹广告，不把分享次数设为门槛。
- 广告中断不授予权益；广告完整看完但保存失败，要保留完成凭据并可重试保存，避免要求重复观看。
- 复测的价值来自新的观察与历史对照，不能把普通波动描述为人格变好或变差。

## 激发分享的内容

最值得分享的是「树＋两个互动伙伴＋主题名＋一句表达自己的话」，而非一大页测评文字。每种主题拥有不同场景和故事：云朵小狗陪旅行、信使猫递信、月兔照顾垂柳、海獭听贝壳。

本版已实现主题海报；单独伙伴卡和成长前后对比海报可作为后续迭代。海报主标题使用「柔软的冒险家」「慢热的浪漫家」等意象，正文保持少量关键词和共鸣文案；“你的树，会是什么样？”形成自然邀请。分享路径只携带公开主题或测试 ID，不携带答题记录 ID、OpenID、逐题选项或完整结果。测试结果不自动公开，用户只在主动保存和分享时选择要展示的内容。

发布到小红书的内容建议围绕可理解的生活情境：忙碌后如何恢复能量、自己的相处节奏、第一棵树与今天的树。标题描述本次体验，不使用“最准确”“官方认证”“测出心理疾病”等未经支持的说法；不编造受欢迎人数或好友动态。

## 已落地的搜索内容

微信原生小程序不使用 H5 网页的 description/meta keywords 作为 SEO 方案。本轮以公开页面的真实内容、原生标题、分享入口与 sitemap 管理可搜索范围：

| 现有内容 | 页面自然标题与关键词 | 承接内容 |
| --- | --- | --- |
| 探索首页 | 人格测试、性格测试、人格测试树 | 六套现有测评介绍、探索进度和测试入口 |
| MBTI | MBTI 性格测试、十六型偏好 | 题量、预计时间、作答提示与测试入口 |
| 大五 | 大五人格测试、五种性格特质 | 开放性、尽责性等现有五维量表内容 |
| 九型 | 九型人格测试、内在动机 | 现有九型测评与基础说明 |
| 内外向 | 内向外向测试、社交能量 | 现有内外向测评与相处节奏文案 |
| SBTI | SBTI 趣味人格测试 | 明确为趣味自我探索 |
| 阴影人格 | 阴影人格趣味测试 | 明确为趣味，不作诊断 |

搜索词直接出现在公开测试卡片、详情页导航标题和分享标题中，不堆砌无关热门词。当前没有独立恋爱关系题库，不为了关键词伪装出尚未提供的恋爱测试服务。关系建议可以属于已有报告解读，但不能宣称等于另一项标准化测试。

`sitemap.json` 只允许探索大厅及公开测试详情页；答题、个人树、档案、历史、隐私页与基础/深度报告均不开放搜索收录。sitemap 控制搜索收录，不能代替云函数中的身份鉴权和数据隔离。

详情页根据真实测试设置导航标题；分享与朋友圈参数只包含公开测试 ID。大厅分享标题覆盖产品名、MBTI、大五和九型，内容与页面实际服务一致。

## 微信后台还需要配置的内容

下列项目需要运营者登录微信公众平台检查并提交，代码无法代替后台审核，也不能保证搜索排名：

1. **名称与简介**：以「人格测试树」建立统一品牌；简介可用“MBTI、大五、九型等性格探索，收集自己的成长树与陪伴伙伴”，最终文字需符合名称、简介及服务类目审核要求。
2. **服务类目**：选择与实际服务及主体资质匹配的类目；仅作自我探索，不按医疗诊断或心理治疗宣传。类目可用性以账号后台为准。
3. **搜索能力**：核对账号是否已开放搜一搜、页面收录或相关服务搜索配置，按实际可见入口提交公开页面与准确服务描述。
4. **版本审核**：核对页面分享、sitemap、广告位与隐私指引；在真机搜索测试产品名称和真实测试词，观察是否能到达正确页面。
5. **小红书内容一致性**：封面风格、主题名称、产品名与微信搜索中的落地页一致，用户搜到后能看见内容中的同一棵树和伙伴。

## 隐私保护与备案不是同一件事

原始逐题选项并非生成本地报告、推荐主题或养树所必需的云端数据，第一版不上传。跨设备恢复才需要可选的结果摘要备份：测试及评分版本、结果类型、维度分数、完成时间、记录标识和已解锁权益；这些内容仅在用户明确启用备份后同步，并按当前微信用户隔离。

微信公众平台的《用户隐私保护指引》需要按实际处理的数据、目的、权限与第三方服务填写，并与小程序里的隐私政策保持一致。运营主体名称、联系方式、处理目的、保存期限与删除入口必须填真实信息，不能用示例代替。协议同意和云备份同意分别处理；用户拒绝备份仍可在本机测试与查看报告。

小程序备案、可能涉及的网站/域名备案，以及微信隐私指引是不同流程。是否需要新增备案、现有主体资质是否匹配，由运营者在微信公众平台及云开发/域名管理后台按真实运营情况确认；隐私政策本身不通过在文档中写“已备案”就完成登记。

本次代码提供本地模式、可选备份、导出和删除入口。正式发布前还必须完成主体与联系信息、微信后台隐私声明、广告服务说明和小程序备案状态核验。

## 发布后观察

优先观察从打开到首次完成、基础结果到主动解锁、首次主题领取、再次探索、海报保存这五个转化环节。统计应使用最少的聚合事件，不上传逐题选项或人格分数；没有用户授权和明确必要性，不额外获取性别、头像、手机号或精确位置。

如果首次完成率低，先看题目长度、按钮与退出位置；如果树页回访低，先让前几次探索都有可见变化；如果分享低，先检查海报能否一屏看懂、角色有没有故事、文案是否像用户自己的表达。广告次数不能代替用户价值。
