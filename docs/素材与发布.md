# 云端美术与发布

环境：`cloud1-d2ghbskq3663254ce`。九套主题场景为独立透明 WebP，另有 `companions.webp`（3 列 × 6 行、18 位伙伴透明精灵图）；当前待审版本的源图放在仓库外的 `treehub-cloud-assets/themes/v2/`，不打进小程序主包或分包。小程序只保存十个云文件 ID 和短期内存 URL。微信加载图片时仍可能使用设备临时缓存，不能承诺完全不产生临时缓存。

线上已发布版本继续读取 `themes/v1/`，该目录视为只读，不覆盖、不删除。当前待审版本的十个 File ID 已切换为 `themes/v2/`。先将仓库 `artifacts/theme-cloud-assets-under-200k.zip` 解压并上传到云端 `themes/v2/`，再编译体验版；每张图片均低于 200KB。审核期间 v1 与 v2 并存，互不影响。

后续每轮美术更新都新建版本目录，例如 `themes/v3/`。只修改 `config/theme-assets.js` 中的 `assetRelease` 和对应 File ID；已经发布过的目录保持不可变。

## 上传美术

运行素材检查，不需要云凭据，也不会发起上传。工具会拒绝任何大于 200000 bytes 的图片：

```sh
node scripts/upload-theme-assets.cjs --source ../treehub-cloud-assets --dry-run
```

有云开发管理员凭据时，在仓库外安装管理端 SDK。凭据只通过当前管理员终端的环境变量提供，不写入项目、小程序代码、截图或聊天：

```sh
npm install --prefix ../treehub-cloud-admin @cloudbase/node-sdk
node scripts/upload-theme-assets.cjs --source ../treehub-cloud-assets --sdk-root ../treehub-cloud-admin
```

上传工具读取 `CLOUDBASE_SECRET_ID`、`CLOUDBASE_SECRET_KEY`，可选临时凭据的 `CLOUDBASE_SESSION_TOKEN`。管理员应给素材目录所需的最小上传权限。工具读取 `config/theme-assets.js` 的 `assetRelease`，当前逐张上传到 `themes/v2/{themeId}.webp`；全部成功后才更新配置，并将实际 fileID 存为素材目录中的 `cloud-manifest.json`。不要把管理端 SDK 安装到小程序源码目录。

也可直接使用已登录的微信云开发控制台，新建 `themes/v2/`，上传九个主题与一张伙伴精灵图共十个 WebP；复制每张文件的实际 fileID，创建以下 JSON（不要用示例代替真实 fileID，也不要选择 v1 文件）：

```json
{
  "environmentId": "cloud1-d2ghbskq3663254ce",
  "assetRelease": "v2",
  "files": {
    "adventurer": "",
    "moon": "",
    "romantic": "",
    "dreamer": "",
    "wanderer": "",
    "listener": "",
    "collector": "",
    "observer": "",
    "aurora": "",
    "companions": ""
  }
}
```

```sh
node scripts/upload-theme-assets.cjs --import-manifest ../cloud-manifest.json
```

素材是可展示的品牌美术，但云存储可以保持“仅创建者可读写”。客户端直连失败时，`treehub-api` 的 `getThemeAssetUrls` 仅为十个 v2 白名单文件生成临时地址，不接受文件路径，也不要求用户开启档案云备份。上传 v2 后必须重新部署云函数，再清除开发者工具缓存验证。隐藏主题的“发现/使用”仍由本地与云端主题权益控制，临时图片地址本身不作为付费内容保护。数据集合继续禁止客户端直接读写。

没有素材配置或断网时显示轻量占位树，保留本地测评、收藏和记录功能；不要把占位树当成最终美术验收。

## 配置与部署

1. 【待验收】确认十张素材位于 `themes/v2/`，重新部署 `treehub-api`，再清除开发者工具缓存并编译；直连或云函数回退任一路径成功即可显示。
2. 核对微信后台隐私保护指引。政策版本修改后，旧备份授权不自动沿用。
3. 按 `cloudfunctions/README.md` 部署云函数与集合权限、索引；旧版自动同步客户端应停止使用，避免绕过新的同意流程。
4. 微信后台完成实际业务对应的类目、简介、隐私保护指引、激励广告位配置和小程序备案信息。前端文档不能代替这些后台提交。
5. 在开发者工具选择当前稳定基础库并用真机检查：首次平台隐私授权、授权后默认备份、拒绝后本地测评、主动关闭后不再自动开启、完整/中途关闭广告、切换菜单、恢复权益和海报生成。当前源码对较新 API 做能力检测。
6. 执行配置检查和回归：

```sh
node scripts/check-release.cjs
node --test tests/*.test.cjs
```

`check-release` 在 fileID 或运营主体未补齐时有意失败；它只检查静态配置，不能证明云函数已部署、数据库权限已生效、平台审核或备案已完成。

## 广告与权益

- 首次有效测评会推荐一套基础主题，用户可在三套基础主题中免费选择。普通主题随对应测试或探索数量自然长出。
- 隐藏主题在完成五类不同测试后自然长出，不要求观看主题广告。
- 深度报告的激励视频只解锁本次测评记录，与主题权益分开。复测的新报告独立解锁。
- 不使用“转发多少人才能解锁”等强制分享；邀请与海报用于自愿展示。
- 当前奖励由微信客户端 `onClose` 的完整观看结果驱动，云端校验归属、白名单、前置探索和重复写入。客户端事件并非防篡改的服务端观看证明，不应宣称具备支付级反作弊能力。以后若引入实际付费权益，需另行接入与平台能力相符的可靠服务端核验。

## 本轮发布前真机复核

先拉取当前分支，重新部署 `treehub-api`（云端安装依赖），确保客户端与云函数的授权版本一致。开发者工具清除编译缓存后重新编译，再上传体验版：

1. 打开未解锁报告，完整看完视频，只解锁这条报告；返回档案再打开仍为已解锁。
2. 打开另一份报告，中途关闭视频不解锁；再次点击可以播放并正常解锁。
3. 连续打开不同报告、退出页面和切换底部菜单，确认没有 `video-ad has been destroyed`，也没有把上一段视频的奖励发给新报告。
4. 模拟断网后点击解锁，应显示失败且按钮可重试；恢复网络再试。已有报告与本地答案仍保留。
5. 档案页点击云同步重试，确认状态变为已同步，并用另一台设备核对恢复结果。两处组件样式警告应消失。

`[worker] reportRealtimeAction:fail not support` 与 `[aiad error] unexpected page benchmark path` 的堆栈来自开发者工具/广告 SDK；项目没有调用这些接口。Node 测试与编译检查不执行微信原生广告，不能据此宣称这两条工具日志已消失。以体验版真机的播放、解锁和同步结果作为最终验收。
