# 持续探索与收藏迭代

本轮补足「答到一半还能回来 → 完成后收藏与分享 → 累积记录后便于回看」的连续体验。测试种类与成长门槛不变，无新增业务媒体文件。

## 本机作答进度

详情页有未完成记录时展示「继续上次」与重新开始入口；普通新测仍默认普通记录。继续作答使用上次选择的生活状态，不把私人状态放进分享链接。

`utils/answer-drafts.js` 将题目版本、评分版本、题目签名、顺序和已选答案保存在独立本机键中，支持 SBTI 随机题序和排序题中间状态。连续点选合并为 500 ms 后一次写入；切到后台或离开时补存。草稿最多 20 项，30 天内可恢复，单项上限 16,000 个 JSON 字符；过期项在后续写入时清理。格式或版本不匹配的进度不恢复。

报告保存成功后清理进度；报告存储失败时保留全部答案供重试。本地 `answerSessionId` 防止清理失败后的旧进度产生重复报告，不加入云端摘要、埋点或分享。既有历史记录无需迁移。清除本地档案时同时清理草稿。

## 结果卡

报告新增两种用户主动生成的卡片：

- 聊天卡：500 × 400，5:4，微信聊天只取此格式。
- 收藏长图：750 × 1000，3:4，适合保存或分享至图文平台。

两种格式独立缓存，最多四张，主题或远端地址变化后失效。仅绘制免费摘要维度、结果短句、日期和已经解析的远端树图；不附带逐题答案、生活事件或私有记录链接。无首屏绘图，不主动申请相册权限。

## 档案和远端图片

档案首屏只传各测试最新一条摘要；展开后每次加载五条。收起时释放界面历史数据，返回页面或完成云同步后保留展开窗口。原始答案、分数和树形快照不随列表摘要传给视图。

以 4,000 条 MBTI 复测记录模拟，首屏 `groups` JSON 从约 519 KB 降到 311 B。该值仅代表示例列表传输量，不代表微信真机启动或渲染耗时。

可运行 `node scripts/benchmark-archive.cjs` 重现当前方案。脚本采用另一组带状态摘要的示例：100／1,000／4,000 条记录的首屏约 322／323／323 B，展开五条约 1 KB；记录 ID 和状态标签会影响具体字节数。

大厅单张插图每次进入最多自动解析两次；持续失败显示原生占位，可手动重试。分享卡、主题海报的远端图片等待最多八秒。页面离开后，海报迟到回调不会自动打开图片。缓存失效后的旧请求不再覆盖新地址，也不会清除新请求的合并标记。

所有新增测试和主题业务图片继续只走云端。原生占位与临时 Canvas 卡片不引入本地素材包。

## 验证与发布

执行 README 中的 Node 回归、WXML/WXSS 编译、依赖与媒体检查。辅助 UI 预览包含详情草稿、档案展开和两种结果卡，仍需微信真机确认：

1. 大五/MBTI 作答数题，切后台及返回；离开后在详情主动继续。
2. 排序到一半离开，恢复原顺序；全部选完但保存失败时可重新生成报告。
3. 生成竖版后分享到聊天，确认仍使用完整横版卡；无横版时先制作聊天卡。
4. 云图片失效、慢网及快速切页时，没有无限请求、长期 loading 或迟到预览。
5. 多次复测后按批回看历史，报告 ID、版本与已解锁权益保持正确。

本轮只改客户端，无新增云集合、授权目的或云函数接口。若尚未部署上一轮的 `themeRulesVersion: 2` 兼容代码，仍需按 [分享与年轮迭代](分享与年轮迭代.md) 的顺序先部署 `treehub-api`。
